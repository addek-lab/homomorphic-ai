KI-Datenschutz-Prüfstand

Immer mehr Menschen geben Arztbriefe, Kontoauszüge und Kreditanträge in KI-Chats ein. Datenschutzfilter sollen das absichern. Aber wie gut sind sie bei deutschen Finanz- und Gesundheitsdaten? Der Prüfstand misst es: mit synthetischen Dokumenten, exakten Lösungen und reproduzierbaren Zahlen.

Live ausprobieren Code auf GitHub ZIP herunterladen

Das Ergebnis auf einen Blick

Zu Presidio, bitte fair lesen: Microsoft Presidio ist ein Baukasten, der für eigene Anpassungen gedacht ist. Getestet wurde Version 2.2 in der Standardkonfiguration mit dem deutschen spaCy-Modell de_core_news_md, dazu der nachträglich aktivierte Kreditkarten-Erkenner (in der Grundeinstellung für Deutsch nicht aktiv). Für Steuer-ID, Versichertennummer, Adressen und Gesundheitsdaten bringt Presidio keine deutschen Erkenner mit. Die vielen Falschalarme entstehen, weil das Sprachmodell Termine, Anreden und Großgeschriebenes als Personen, Orte oder Daten meldet; jede Erkennung ohne sensible Angabe zählt hier als Falschalarm. Das ist kein Urteil über das Produkt, sondern der Ausgangspunkt, den man ohne eigene Anpassung bekommt. Die Namenserkennung ist dabei besser als die meiner Referenz-Regeln. Presidio läuft nur in der Python-Auswertung, das Live-Demo unten nutzt die beiden Regelwerke.

Geschützt nach Art der Angabe

„Geschützt“ heißt: mindestens 80 % der Zeichen der Angabe werden von der Erkennung überdeckt. ⚠ = als kritisch eingestuft (Finanz- und Gesundheitsdaten).

Warum das für Finanz- und Gesundheits-IT zählt

GESUNDHEIT

Gesundheitsdaten gehören nach der DSGVO (Art. 9) zu den besonderen Kategorien. Wer sie an einen KI-Dienst schickt, braucht belastbare Maßnahmen. Ein Filter, der Diagnosen im Fließtext übersieht, ist keine.

FINANZEN

IBAN, Steuer-ID und Kartendaten sind Kernbereiche der Finanz-Compliance. Kartendaten unterliegen zusätzlich dem Branchenstandard PCI DSS. Prüfsummen helfen, sie von bloßen Zahlenfolgen zu unterscheiden.

NACHWEIS

„Wir filtern personenbezogene Daten“ ist eine Behauptung. Ein reproduzierbarer Test mit festen Zahlen ist ein Nachweis. Genau das fehlt in den meisten Datenschutz-Dokumentationen für KI-Einsatz.

Diese Einordnung ist Orientierung und keine Rechtsberatung. Pseudonymisierte Daten bleiben nach der DSGVO oft personenbezogen. Ob ein Verfahren für einen konkreten Einsatz reicht, klären Datenschutzbeauftragte oder Juristen.

Methodik und Grenzen

  • Daten: Ein Generator erzeugt deutsche Dokumente (Arztbrief, Überweisung, Kreditantrag, Support-Ticket, Kostenübernahme, Kontoauszug, Beschwerde) mit exakten Annotationen. Alles ist erfunden; IBAN, Kreditkarte, Steuer-ID und KVNR haben gültige Prüfziffern.
  • Störgrößen: Termine, Auftrags- und Artikelnummern, Hotlines und Anreden wie „Herr Kundenberater“ sehen nach Personendaten aus, sind aber keine. So werden Falschalarme messbar.
  • Zuordenbar heißt: Ein Name oder die Kombination aus Geburtsdatum und Wohnort bleibt sichtbar. Das ist eine einfache Heuristik und kein Re-Identifikationsmodell.
  • Die Referenz-Regeln stammen vom Autor und kennen die Formate des Generators. Sie sind eher eine Obergrenze für regelbasierte Erkennung als ein Abbild der Praxis. Wortlisten für Namen, Medikamente und Diagnosen sind bewusst nur teilweise bekannt.
  • Synthetische Daten sind sauberer als echte. Die Zahlen zeigen Muster und Größenordnungen, keine Gütesiegel. Die KVNR-Prüfziffer folgt meinem Verständnis der öffentlichen Beschreibung und ist nicht offiziell verifiziert.
  • Reproduzierbar: Gleicher Seed, gleiche Dokumente, gleiche Zahlen. Die Browser-Version liefert auf 80 Testdokumenten dieselben Treffer wie die Python-Version.

Teste dein eigenes Werkzeug

Der Prüfstand läuft ohne Zusatzpakete (nur Python 3). Ein eigener Filter braucht eine Funktion, die zu einem Text die gefundenen Stellen liefert.

python -m pruefstand run --html bericht.html
python -m pruefstand run --plugin mein_filter.py:detect
python -m pruefstand demo
python -m unittest discover -s tests
import re

def detect(text):
    # (start, ende, typ) je gefundener Stelle
    return [(m.start(), m.end(), "EMAIL")
            for m in re.finditer(r"[\w.+-]+@[\w.-]+", text)]
